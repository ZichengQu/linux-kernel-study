# 内核补丁合入与提交流程

本文记录内核补丁合入、生成、检查、邮件提交及版本迭代的常用操作。

## 1. 合入补丁

应用补丁并添加 Signed-off-by，随后检查是否存在未成功应用的内容：

```bash
git am <name>.patch --reject -s
find . -name "*.rej"
```

如存在 `.rej` 文件，需处理其中未能应用的改动，检查结果后再继续合入流程。

## 2. 生成与检查补丁

`--subject-prefix` 必须注明补丁回合到主仓的目标分支名，下面以 `openEuler-1.0-LTS` 分支为例：

```bash
git format-patch -1 --subject-prefix="PATCH openEuler-1.0-LTS V1"
./scripts/checkpatch.pl <name>.patch
```

制作补丁系列时，以下命令将最近两个提交导出为补丁，并生成封面信：

```bash
git format-patch -2 --subject-prefix="PATCH" --cover-letter
```

向目标主仓分支提交系列补丁时，同样需要在 `--subject-prefix` 中补充目标分支名及版本号；发送前编辑封面信，说明系列补丁的目的和主要改动。

## 3. 发送补丁

### 发送给自己预检

```bash
git send-email --to author@example.com --suppress-cc=all <name>.patch
```

### 发送给内部审核平台

```bash
git send-email --to patchwork@huawei.com \
  --cc author@example.com \
  --suppress-cc=all <name>.patch
```

### 发送给 openEuler 社区审核

按需要抄送相关审核人：

```bash
git send-email --to kernel@openeuler.org \
  --cc reviewer1@example.com \
  --cc reviewer2@example.com \
  --cc reviewer3@example.com \
  --cc author@example.com \
  --suppress-cc=all <name>.patch
```

仅抄送一位审核人和自己的简化示例：

```bash
git send-email --to kernel@openeuler.org \
  --cc reviewer1@example.com \
  --cc author@example.com \
  --suppress-cc=all <name>.patch
```

## 4. 向上游社区提交补丁

查询补丁涉及的维护者和邮件列表：

```bash
scripts/get_maintainer.pl <name>.patch
```

根据查询结果填写收件人；有多个收件人时，可重复使用 `--to` 参数：

```bash
git send-email --to <linux-maintainers> \
  --cc reviewer1@example.com \
  --cc reviewer2@example.com \
  --cc reviewer3@example.com \
  --cc author@example.com \
  --suppress-cc=all <name>.patch
```

## 5. 更新补丁版本与邮件交流

根据审核意见修改代码及提交说明后，生成 v2 补丁：

```bash
git format-patch -1 <commit-id> --subject-prefix="PATCH v2"
```

如果提交到指定主仓分支，还应在前缀中保留目标分支名，例如 `PATCH openEuler-1.0-LTS V2`。

在补丁邮件正文中补充版本变更记录（changelog），通常放在 `---` 分隔线之后，说明相对上一版的修改，避免将仅用于邮件交流的记录加入提交说明。

通过 `--in-reply-to` 关联之前的补丁邮件，使用原邮件的 Message-ID：

```bash
git send-email --to <linux-maintainers> \
  --cc reviewer1@example.com \
  --cc reviewer2@example.com \
  --cc reviewer3@example.com \
  --cc author@example.com \
  --suppress-cc=all \
  --in-reply-to='<message-id>' \
  <name>.patch
```
